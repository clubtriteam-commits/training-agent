# Spec: `personal_bests`

> Status: **одобрена — чака Фаза 0 (Sheet таб).** Двете допускания от предишната чернова са потвърдени: 3 дисциплини (бягане/плуване/колоездене), таб `PBs` в съществуващия `local_results` Sheet.

## 1. Цел

Треньорът поддържа ръчно личните рекорди на атлетите извън триатлон-контекста — самостоятелни резултати от лека атлетика (писта/шосе), плуване и колоездене, които не идват от `world_triathlon_results` или `local_results` (тези таблици покриват само триатлон/дуатлон/акватлон старт, не самостоятелна дисциплина). Целта е тези данни да влязат в SQLite през същия read-only Sheet-sync модел като `race_courses`/`local_results`/лактатните тестове, и да се покажат в нова секция на `athlete.php`.

**Потвърдено:** обхватът е **трите дисциплини** — бягане (писта + шосе), плуване (басейн) и колоездене. `discipline` е свободен текст в схемата (виж §3), така че третата стойност не изисква структурна промяна — само нови редове в Sheet-а.

## 2. Източник

- **Sheet ID:** същият `LOCAL_RESULTS_SHEET_ID` — **потвърдено**, нов таб в същия Sheet (по прецедента на `race_courses`, едно място за треньора).
- **Таб:** `PBs`
- **Service account / достъп:** същият read-only service account като останалите Sheet sync-ове.
- **Интерпретатор:** venv Python 3.11 (`./venv/bin/python fetch_personal_bests.py`).

### Колона → поле (предложение — таб още не съществува, чака Фаза 0)

| Sheet колона | `personal_bests` поле | Тип | Пример |
|---|---|---|---|
| `Атлет` | `athlete_name` | TEXT | `Мира Иванова` |
| `Дисциплина` | `discipline` | TEXT | `бягане`, `плуване`, `колоездене` |
| `Дистанция` | `event` | TEXT | `1500м писта`, `5000м писта`, `10км шосе`, `400м басейн`, `20км временен старт` |
| `Резултат` | `result` | TEXT | `4:32.10` |
| `Дата` | `date` | TEXT (ISO) | `2026-04-12` |
| `Бележки` | `notes` | TEXT | свободен текст, по избор |

`event` умишлено свободен текст, не enum — покрива едновременно фиксираните писта/басейн дистанции и отворените шосейни разстояния ("и тн."), по същия принцип като `distance_type` в `race_courses`.

**Семантика на реда:** един ред = **текущият** личен рекорд на атлета за тази дисциплина+дистанция, не исторически лог на всеки опит. Когато атлетът подобри рекорд, треньорът **редактира съществуващия ред** в Sheet-а (не добавя нов) — sync-ът презаписва по `(athlete_name, discipline, event)`.

## 3. Схема

```sql
CREATE TABLE IF NOT EXISTS personal_bests (
    athlete_name    TEXT NOT NULL,
    discipline      TEXT NOT NULL,
    event           TEXT NOT NULL,
    result          TEXT,
    date            TEXT,
    notes           TEXT,
    synced_at       TEXT DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (athlete_name, discipline, event)
);
```

| Column | Type | Notes |
|---|---|---|
| `athlete_name` | TEXT | Join по име, не по ID — същия компромис като `lactate_tests`/`local_results` (ADR 0004). |
| `discipline` | TEXT | `бягане` / `плуване`, свободен текст (не DB enum), но UI-то групира по тази стойност. |
| `event` | TEXT | Свободен текст — конкретна дистанция/тип старт. |
| `result` | TEXT, nullable | Час:мин:сек като низ, същия формат като другите time полета в проекта (`total_time` и т.н.), не секунди-число. |
| `date` | TEXT, nullable | ISO `YYYY-MM-DD`, по избор — треньорът може да не помни точна дата за стар рекорд. |
| `notes` | TEXT, nullable | Свободен текст. |
| `synced_at` | TEXT (auto) | |

**Unique constraint:** `(athlete_name, discipline, event)` — самата PRIMARY KEY.
**Update frequency:** ръчно след Sheet редакция, **без cron** (личните рекорди се сменят рядко) — същото решение като `race_courses`.
**Written by:** `fetch_personal_bests.py:sync_personal_bests()`.
**Read by:** `athlete.php` (нова секция "Лични рекорди" — Фаза 4).

## 4. Нормализации

- **Празна клетка → `NULL`**, никога `""`.
- **`result` остава TEXT без parse** — не се опитва да се вкара в секунди при sync (за разлика от `rc_time_to_seconds()` в `results_comparison.php`, който смята delta client-side/render-side от готов текстов формат) — консистентно с как `total_time` вече се пази другаде в базата.
- **Header matching:** точно съвпадение на български имена на колони, без fallback за преименувана колона — същия съзнателен риск, приет вече за `race_courses`.
- **Дубликат ред в Sheet-а** (същия `athlete_name`+`discipline`+`event` два пъти): последният ред печели (`INSERT OR REPLACE`), без warning — приемливо за таб, който треньорът поддържа ръчно и рядко.

## 5. Join логика

Няма join към `world_triathlon_results`/`local_events` — за разлика от `race_courses`, тези данни са напълно самостоятелни (не WT състезание с `event_id`). Единствената връзка е `athlete_name` към `athletes.yaml`, проверявана като orphan (виж §6).

## 6. Validation заявка (за `scripts/audit_data.py`)

Не е нужна нова custom проверка — `personal_bests` се добавя към съществуващия tuple в проверка 1 (`check_orphans`, `scripts/audit_data.py:132`):

```python
for table in ('lactate_tests', 'local_results', 'nat_functional_tests', 'personal_bests'):
```

Това автоматично flag-ва редове с `athlete_name`, който не съвпада с никой в `athletes.yaml` — същата логика като другите три Sheet-базирани таблици, без нужда от отделна функция.

## 7. Dashboard surface (кратко — детайлно проектиране във Фаза 4)

Нова секция "Лични рекорди" на `athlete.php`, отделна от "Резултати по година"/"Местни състезания" (не е триатлон резултат). Групирано по `discipline` (Бягане / Плуване / Колоездене като три под-блока), вътре сортирано по `event`. Компактна таблица: Дистанция / Резултат / Дата / Бележки. Добавям котва в съществуващия `.page-nav` (най-вероятно нова 5-та точка, или влиза в групата "Състезания" — решавам в Фаза 4 по действителния DOM ред, същия принцип като UI/UX одита). Без нови JS библиотеки.
